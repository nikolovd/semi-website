# Полупроводникови елементи

Минималистичен учебен сайт на български за университетски курс с лекции и упражнения.
Секцията „Лекции“ съдържа седем примерни теми с места за презентации.
Работи директно в браузър и с GitHub Pages, без инсталация на пакети,
JavaScript или компилация.

## Структура

```text
semi-website/
├── index.html     # Съдържание на сайта
├── style.css      # Цветове, типография и адаптивно оформление
├── .nojekyll      # Публикуване без обработка с Jekyll
├── .gitignore     # Изключване на системни файлове
├── .gitattributes # Съществуващи настройки на Git
└── README.md      # Тези указания
```

## Преглед на компютъра

Отворете `index.html` с браузър. Дръжте `style.css` в същата папка.
Упражненията се разгъват при натискане върху заглавието им.

## Публикуване чрез GitHub Desktop

1. Отворете GitHub Desktop и изберете `semi-website`.
   Ако липсва, използвайте **File → Add Local Repository** и посочете
   папката на това хранилище.
2. В **Changes** проверете и маркирайте файловете на сайта.
3. В полето **Summary** напишете `Add course website`.
4. Натиснете **Commit to main** (или името на текущия клон).
5. Ако хранилището още не е в GitHub, натиснете **Publish repository**,
   оставете името `semi-website` и изключете **Keep this code private**
   за публичен сайт с GitHub Free. Потвърдете с **Publish Repository**.
   Ако вече е публикувано, натиснете **Push origin**.
6. Изберете **Repository → View on GitHub**.

## Включване на GitHub Pages

1. В GitHub отворете **Settings → Pages** на хранилището.
2. Под **Build and deployment → Source** изберете **Deploy from a branch**.
3. Под **Branch** изберете клона, в който качихте файловете
   (обикновено `main`), и папката **/ (root)**.
4. Натиснете **Save**.
5. Изчакайте публикуването. То може да отнеме до 10 минути.
   Адресът ще се появи в **Settings → Pages**.

За това име на хранилище адресът обичайно е:

`https://YOUR-USERNAME.github.io/semi-website/`

Заменете `YOUR-USERNAME` с името на вашия GitHub профил или организация.
Не е необходим собствен домейн или платен сървър.

## Следващи промени

Редактирайте локалните файлове, проверете страницата в браузър,
направете **Commit** в GitHub Desktop, после **Push origin**.
GitHub Pages публикува обновената версия автоматично.

## Попълване на курса

Редактирайте `index.html`, за да добавите реалните контакти,
дати, зали, срокове и условия за оценяване. Графикът и задачите
и лекционните теми са примерни, а материалите и контактите са обозначени за попълване.

За материали създайте папка `materials`, качете действителен файл,
например `exercise-01.pdf`, и заменете съответното съобщение
„Предстои добавяне на файл“ с:

```html
<a href="./materials/exercise-01.pdf">Указания за упражнение 1 (PDF)</a>
```

Използвайте относителни пътища, започващи с `./`, за да работят
и под адреса `/semi-website/`. Имената на файловете са чувствителни
към главни и малки букви.

Цветовете се променят чрез променливите в началото на `style.css`.
При печат разгънете упражненията, които искате да включите.

## Добавяне на лекционни презентации

В секцията `#lectures` на `index.html` заменете „Презентация: предстои добавяне“
с връзка към действително качен файл, например:

```html
<a href="./materials/lecture-01.pdf">Презентация към лекция 1 (PDF)</a>
```

Първо поставете `lecture-01.pdf` в папката `materials` и качете файла
заедно с промяната в страницата.

## Ако сайтът не се показва

- Проверете дали `index.html` и `style.css` са в основната папка
  на избрания за публикуване клон.
- Уверете се, че сте натиснали **Push origin**, а не само **Commit**.
- Проверете **Settings → Pages** за правилния клон и **/ (root)**.
- Проверете раздела **Actions** за неуспешно публикуване.
- Ако липсва оформление, проверете дали `style.css` е качен и
  презаредете страницата с `Command + Shift + R` на Mac.
